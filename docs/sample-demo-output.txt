This PR adds coupon validation and application logic to the checkout flow, 
including expiry, usage limits, and minimum order total checks. The 
implementation has several issues including a race condition on usage counts, 
silent failure on invalid coupons, and a bare except clause that could mask 
real errors.

F1  HIGH   Race condition on coupon usage count  
orderflow/services/coupons.py:19
     The usage count is checked before the order is committed, so two 
concurrent requests can both see the count below max_uses and both apply the 
coupon, exceeding the limit. Use a database-level constraint or a SELECT ... 
FOR UPDATE on the coupon row to serialize access, or increment a counter 
atomically and check the result.

F2  MEDIUM Silent failure on invalid coupon  orderflow/services/coupons.py:14
     When the coupon is not found, expired, over limit, or below min_total, the
function just prints a message and returns the order unchanged. The caller has 
no way to distinguish 'coupon applied' from 'coupon rejected' without 
inspecting order.coupon_id. Raise a specific exception (e.g., 
CouponNotFoundError, CouponExpiredError) so the API layer can return a 
meaningful error to the user.

F3  MEDIUM Bare except swallows all exceptions  
orderflow/services/coupons.py:44
     The bare except in remove_coupon will catch KeyboardInterrupt, SystemExit,
and any programming error, then silently roll back and return the order as if 
nothing happened. Catch a specific exception (e.g., SQLAlchemyError) and log 
the error so failures are visible.

F4  LOW    Use structured logging instead of print  
orderflow/services/coupons.py:15
     print() calls will not appear in production log aggregators and cannot be 
filtered by level. Replace with a module-level logger 
(logging.getLogger(__name__)) and use logger.info / logger.warning as 
appropriate.

F5  LOW    datetime.utcnow() is deprecated  orderflow/services/coupons.py:18
     datetime.utcnow() is deprecated in Python 3.12+ and returns a naive 
datetime. Use datetime.now(timezone.utc) instead to get a timezone-aware 
datetime, which also avoids ambiguity if the database stores timezone-aware 
timestamps.
